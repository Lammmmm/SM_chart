# 聪明钱推断名单批次分析（逻辑版本 2.1）

## 最重要的数据边界

- 原始历史文件 `smart_money_cache.json` 永远只读，不删除、不改写，也不需要重新抓取。
- 现有约 95 天历史数据会自动重新划分名单批次，只用于开发和探索性回测。
- 模型冻结时间固定在 2026-08-27T01:42:59Z，当前修正版逻辑生效时间为 2026-08-27T04:27:07Z。只有同时晚于这两个边界的数据才属于 2.1 的真正样本外验证。
- 币安抓取和本地缓存逻辑保持原样；所有新结果写入 `data/derived/`。

## “推断名单批次”是什么意思

币安没有提供可完整跨日追踪的 Smart Trader 身份集合，所以本项目不能知道具体哪些账户保持不变。这里的批次只表示：一次疑似名单刷新稳定后，到下一次疑似刷新前的“推断稳定样本窗口”。

系统保留原人数跳变检测，并使用只看过去 24 小时数据的稳健结构异常分数辅助识别人数近似不变但统计结构发生变化的刷新。结构判断会综合交易者人数、平均开仓价、BTC 等价数量代理、未实现盈亏和多空比；仓位和盈亏不能单独触发刷新。

已经进入正式有效期的批次一旦再次出现人数或结构刷新，必须立即创建新的批次编号，不能复用旧基准。只有名单刷新期、稳定观察期和基准构建期内的连续跳变才会合并为同一轮刷新。

默认研究只使用高可信和中可信批次。低可信批次不生成研究信号；批次超过 26 小时或数据中断超过 2 小时后也会停止生成信号，直到重新建立稳定基准。宁可舍弃不确定数据，也不把跨名单变化误解成主动加减仓。

## 亏损过程与动作事件

逻辑版本 2.0 将事件时间拆开；2.1 进一步修复 USDT 名义仓位的价格污染：

- USDT 名义仓位约等于真实 BTC 风险数量乘以 BTC 价格，因此 BTC 自身上涨可能在没有加仓时制造名义金额上涨。
- `long_qty_proxy = long_pos_usdt / current_price`，空头同理。它是 BTC 等价数量代理，不是 Binance 提供的账户级精确合约张数。
- cohort baseline 先逐条计算数量代理，再取代理值的中位数；不会使用“仓位中位数 ÷ 价格中位数”。
- 加仓和减仓只由相对亏损起点的数量代理变化首次越过 ±3% 触发。
- USDT 名义仓位变化和名义净流继续保留用于兼容及描述，但不再用于动作、结构刷新或主要背离信号。

- “首次进入新亏损”发生在亏损第一次越过门槛的时刻。
- “亏损后首次明显加仓”发生在仓位第一次越过加仓门槛的时刻。
- “亏损后首次明显减仓”发生在仓位第一次越过减仓门槛的时刻。
- 同一个亏损过程可以先加仓再减仓，也可以先减仓再加仓；每类动作最多记录第一次越界。
- 持仓不是瞬时事件，只能描述截至某个观察窗口仍未出现加仓或减仓。

例如 10:00 首次亏损、13:00 首次明显加仓：新亏损的 1 小时收益使用 10:00→11:00，而加仓事件的 1 小时收益必须使用 13:00→14:00。13:00 之前的数据不会因为未来发生加仓而被重新分类。

未来目标价格只使用目标时刻之后 15 分钟内的第一条记录，不会把缺失的 1 小时收益偷偷替换成 2 小时或 3 小时收益。

旧逻辑生成的 `LONG/SHORT_NEW_LOSS_ADD/REDUCE` 回测全部作废，因为它使用未来动作分类，却从亏损起点计算收益。2.0 中直接用 USDT 名义仓位 ±3% 判断动作的结果同样作废，因为受到 BTC 价格机械变化污染。旧字段仅为兼容和对照保留，不得用于因果回测。

## 一条命令完成全部分析

中文命令：

    python smart_money_analysis.py 处理聪明钱

兼容原技术命令：

    python smart_money_analysis.py process-smart-money

以上命令会依次完成：

1. 原始记录质量检查。
2. 自动识别推断名单批次刷新并给出高、中、低可信度。
3. 等待名单稳定并建立中位数基准。
4. 分别计算 USDT 名义仓位描述值和用于研究的 BTC 等价数量变化、数量净风险流。
5. 识别已有亏损与新亏损。
6. 分别生成亏损过程、首次加仓和首次减仓事件。
7. 从各自真实事件时刻计算未来 1、4、12、24 小时比特币收益。
8. 输出仅高可信与高+中可信两套回测，并与同批次非事件时点的无条件收益比较。
9. 生成中文分析报告。

仅查看已有中文报告：

    python smart_money_analysis.py 查看聪明钱报告

## 推荐直接阅读的中文文件

- 聪明钱分析报告_中文.md：最易阅读的完整摘要和回测结果。
- 聪明钱回测结果_中文.csv：中文表头的总体及分组回测。
- 聪明钱逐条分析_中文.parquet：中文列名的逐条分析结果。
- 聪明钱亏损过程表_中文.parquet：中文列名的完整亏损过程。
- 聪明钱动作事件表_中文.parquet：中文列名的首次加仓、首次减仓事件。
- 聪明钱动作定义对照_中文.csv：旧 USDT 名义动作与新 BTC 等价数量动作的逐事件对照。
- 聪明钱事件表_中文.parquet：兼容使用的合并事件表，并带有事件类别。
- 聪明钱批次表_中文.parquet：中文列名的名单批次表。

原有英文文件是程序使用的兼容格式，可以不看。

## 测试

当前 Python 环境有一个与本项目无关的第三方测试插件版本冲突，因此运行测试时需要关闭全局插件自动加载：

    $env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
    python -m pytest tests/test_smart_money_analysis.py -q

所有阈值都集中在 `smart_money_analysis_config.json`，并附有中文解释。本轮没有修改亏损、恢复、加仓、减仓或冷却阈值。现有约 95 天历史仍可按 2.1 重算，但全部属于探索数据；只有修正版逻辑生效时间之后新产生的数据才进入真正样本外验证。
